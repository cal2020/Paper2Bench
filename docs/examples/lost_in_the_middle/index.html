## Experimental Design

1. **Multi-Document Question Answering (MDQA)**
   - **Procedure**: 
     - Input consists of a question and `k` documents (where `k` can be 10, 20, or 30). Each document is a chunk of at most 100 tokens from Wikipedia.
     - The relevant document containing the answer is placed at different positions (beginning, middle, end) within the input context.
     - For each query, retrieve `k-1` distractor documents that do not contain the answer using a retrieval system fine-tuned on MS-MARCO.
     - Use the following configurations for `k`: 10, 20, and 30 documents.
   - **What to Record**: 
     - Accuracy of the model's predictions, specifically whether the correct answer appears in the output.
   - **Correspondence**: 
     - Results are illustrated in Figure 5 and summarized in Table 1.

2. **Synthetic Key-Value Retrieval Task**
   - **Procedure**: 
     - Input consists of a JSON object with `k` key-value pairs (where `k` can be 75, 140, or 300). Each key and value is a unique randomly-generated UUID.
     - The relevant key is placed at different positions within the JSON object.
     - For each configuration, evaluate the model's ability to return the value associated with a specified key.
   - **What to Record**: 
     - Accuracy of the model's predictions, specifically whether the correct value appears in the output.
   - **Correspondence**: 
     - Results are illustrated in Figure 7.

3. **Model Architecture Comparison**
   - **Procedure**: 
     - Compare the performance of decoder-only models (e.g., GPT-3.5-Turbo, MPT-30B-Instruct) against encoder-decoder models (e.g., Flan-T5-XXL, Flan-UL2) on long input sequences.
     - Use the same input context length as in the MDQA task, varying the position of relevant information.
   - **What to Record**: 
     - Accuracy of the models across different positions of relevant information.
   - **Correspondence**: 
     - Results are illustrated in Figure 8.

4. **Query-Aware Contextualization**
   - **Procedure**: 
     - Implement query-aware contextualization by placing the query before and after the documents in the input context.
     - Evaluate the performance of models on the synthetic key-value retrieval task with and without query-aware contextualization.
   - **What to Record**: 
     - Accuracy of the models on the key-value retrieval task.
   - **Correspondence**: 
     - Results are illustrated in Figure 9.

## Evaluation Details

- **Metrics**: 
  - Accuracy is defined as the percentage of correct answers returned by the model. 
  - For multi-document QA, accuracy is calculated as:
    \[
    \text{Accuracy} = \frac{\text{Number of Correct Answers}}{\text{Total Questions}} \times 100
    \]
  - For key-value retrieval, accuracy is similarly calculated based on the number of correct values returned.

- **Normalization/Pre-processing**: 
  - Ensure that the model outputs are stripped of any extraneous text and only the predicted answers are considered for scoring.

- **Aggregation Strategy**: 
  - Calculate per-sample accuracy for each model and condition, then average these to obtain per-condition accuracy, and finally compute overall accuracy across all conditions.

## Implementation Notes

- **Key Pitfalls**: 
  - Ensure that the distractor documents are truly irrelevant to avoid misleading performance metrics.
  - Be cautious of the model's context length limitations; ensure that the input does not exceed the maximum token limit for each model.

- **Prompt Templates**: 
  - Use the following prompt template for the multi-document QA task:
    ```
    Write a high-quality answer for the given question using only the provided search results (some of which might be irrelevant).
    Document [1]: ...
    Document [2]: ...
    ...
    Question: {question}
    Answer:
    ```

- **Order of Operations**: 
  - For each experiment, ensure that the input context is constructed correctly before passing it to the model.
  - Record outputs immediately after model inference to avoid any discrepancies in results due to changes in input or model state.
